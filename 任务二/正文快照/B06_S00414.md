# Ask HN: A high level language that compiles to VBA ?

- 来源：Hacker News
- 链接：https://news.ycombinator.com/item?id=6204640
- 发布时间：2013-08-13
- 热度：点赞4、评论12

## 正文
I don't have a lot of background in computer science (4 years), but it seems to me that recently, we saw some new languages coming alive.I just heard of Elixir which is built on top of the Erlang VM. Scala is a little bit older (2003) and targets JAVA VM. Clojure(2007) targeting JAVA VM and being compilable to javascript, seems to be a really clever move. Javascript rising popularity have triggered the rise of transpilers that targets that language. My point is that designing high level language that transpiles to another seems to be a pretty active field. I guess that tools to do so have evolved in the recent history (I actually would be interested to know about the state of the art, any resources are very welcome). Leveraging an existing platform by adding concept-comprehension at the syntactic level (i'm thinking of list comprehension, for example) seems to add productivity at no cost, no trade-off (?) OK now, the real topic. In my opinion, VBA is as annoying to write as it is present in the industry. A lot of companies rely on it (I'm working in the financial industry, so mainly VBA for Excel). A lot of people uses VBA, a lot of people already have that tool, and struggle to use it,and still use it. VBA allows you to do what you want to do, but I don't think it is optimal to directly write VBA. I think of it as a telegraph line: the network is already there, Morse code allows you to write anything you want, but it a PITA to work with. Build a tool that automatically encodes and decodes what's on the channel and you're on the internet (OK, oversimplifying here). Can't we put excitement back in VBA technology by hiding it ? I'm sure we have tools to make it happen. I really would love to have developer's opinion on that. If you think that nobody has ever been that wrong, please include enlightenments.
