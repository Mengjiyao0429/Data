## 正文
When using a Custom Agent Engine, the OAuth2 /authorize call generated by the preview interface (Vertex AI Search) fails because it is missing the mandatory response_type=code parameter. App Console Agent Preview Auth Type: OAuth2 with PKCE ( S256 ) Steps to Reproduce: Created a Gemini Enterprise app and connected a Custom Agent Engine. Configured Authorization by providing the client_id , client_secret , token_uri , and authorization_uri . Enabled the Agent and navigated to the App > Overview to preview the agent. Entered a prompt that triggers the custom tool/agent. Clicked the prompt to Authorize when requested. The browser redirects to the IdP, but the IdP returns an "unsupported response type" error. The generated URL intercepted during the failure is: oauth2/<authServerId>/v1/authorize?client_id=abc123&state=xxx&code_challenge=uuu&code_challenge_method=S256&redirect_uri=https%3A%2F%2Fvertexaisearch.cloud.google.com%2Foauth-redirect The response_type parameter is entirely absent from the query string. I expected the URL to include &response_type=code to comply with standard OAuth2 Authorization Code Grant flows. Can this be confirmed as a bug in the Agent Engine's request generator? Is there a way to manually append or force the response_type Agent Engine Reasoning Engine configuration?
