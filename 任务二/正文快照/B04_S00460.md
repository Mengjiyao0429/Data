## 正文
The example code in the official doc of concurrent.futures.ProcessPoolExecutor() : import concurrent.futures import math PRIMES = [ 112272535095293, 112582705942171, 112272535095293, 115280095190773, 115797848077099, 1099726899285419] def is_prime(n): if n < 2: return False if n == 2: return True if n % 2 == 0: return False sqrt_n = int(math.floor(math.sqrt(n))) for i in range(3, sqrt_n + 1, 2): if n % i == 0: return False return True def main(): with concurrent.futures.ProcessPoolExecutor() as executor: for number, prime in zip(PRIMES, executor.map(is_prime, PRIMES)): print('%d is prime: %s' % (number, prime)) if __name__ == '__main__': main() runs without any issues in a jupyter notebook in a ubuntu system, but fails with a "BrokenProcessPool: A process in the process pool was terminated abruptly while the future was running or pending." error in a jupyter notebook in Visual Studio Code in a Windows 10 system. "Python 3.10.10 | packaged by Anaconda, Inc. | (main, Mar 21 2023, 18:39:17) [MSC v.1916 64 bit (AMD64)] on win32" I have consulted several posts that discuss this. So yes, I know from this post and from my own tests that I can put the code in a .py script and call it from the notebook. That works. And yes, I know (vaguely) that Windows behaves differently from other systems in creating processes, threads, etc.; this post briefly mentions it; but there does not appear to be a conclusion/solution. So the point remains: given that it's claimed that this code should work in Windows, is there anything one can do to be able to run the code as per official documentation, in a jupyter notebook, in Visual Studio Code, in Windows 10? Using a separate .py script has many inconveniences vs running the code in a notebook cell. It just seems bizarre to me that official documentation should have code that clearly does not work in a major operating system, forcing every single person who encounters this error to go looking for workarounds and finding N different and quite inconvenient solutions. Unless there is something wrong with my python installation or settings, but most other code works fine, so... BTW, for the record, I did also try some of the solutions that recommended to use multiprocessing Pool and similar; that resulted in the notebook cell freezing forever. EDIT after a lot of further browsing, I found a possible solution that still allows to run the multiprocessing part in a notebook, only moving the worker function to a .py The example shown in the above post works in Visual Studio Code. I imagine that for the example in the concurrent.futures.ProcessPoolExecutor() one would have to move the definition of is_prime to a .py and import it; not sure about the with part. To be tried.
