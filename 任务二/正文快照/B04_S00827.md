## 正文
This question is about when to use and inject delegates vs intantiating objects. Say I want to model a card game, I might want to inject the behavior for building the deck and shuffling. Since these are pure, stateless methods they seem like an ideal candidate to be static. It seems silly to be instantiating instances of a class to execute a function. However as a project scales up we begin to worry about deep nesting of objects, increased complexity, and unit testing. What is a good practice here for a large, complex project? Is the static route workable. I know C# is an OO first language so it encourages using the object instances. What considerations go into this decision?
