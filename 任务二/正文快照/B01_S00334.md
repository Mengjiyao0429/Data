# Why Is Version Control Still So Complicated in 2024?

- 来源：Hacker News
- 链接：https://news.ycombinator.com/item?id=42256437
- 发布时间：2024-11-27
- 热度：点赞3、评论6

## 正文
I’m a self-taught programmer who never worked in a formal software engineering role, and until recently, I mostly coded solo. Now that I’m collaborating on projects with friends, I’ve realized just how cumbersome Git and GitHub can be. Simple tasks like saving my changes, seeing what my colleagues did, merging work, or reverting to an earlier version often turn into frustrating battles with the command line. Errors, merge conflicts, and unexpected behaviors feel like the norm. It feels like everything else in coding —designing, debugging, deploying— has become so much more accessible with LLMs and modern tools. But version control? It still feels like it's stuck in the early 2000s. Why hasn’t this changed? Shouldn't version control be as intuitive as using Google Docs by now? This has me wondering: would there be demand for a “GitHub but dead simple”? Imagine something with: - Autosaves (like Google Docs for code) - A visual timeline/history of changes - Automated merging and conflict resolution powered by AI - Natural language search through repo files Would anyone else find this useful? Or am I just bad at Git?
