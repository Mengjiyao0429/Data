## 正文
I'm running a BackgroundTask in FastAPI that uses Langchain's RecursiveCharacterTextSplitter to split text into chunks. The function is synchronous, and would block the endpoint from returning the response before the BackgroundTask is executed, so I used FastAPI's run_in_threadpool to allow me to await the text splitter. After this addition, the function no longer blocks. My issue now is that the endpoint consumes a large amount of memory, resulting in worker timeouts. Additionally the memory that the endpoint consumes is not fully recovered after the process is complete. Not sure what to do at this point. I've created a repository containing a minimal, reproducible example here . Potentially related posts: No objects ever released by the GC, potential memory leak? The memory usage piles up over the time and leads to OOM
