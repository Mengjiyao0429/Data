## Title: US-76 AI Chatbot · 对话创建新行程 **Parent:** US-59 AI Chatbot 智能行程规划（Epic）· **Size:** M · **Change:** add-trip-planning-agent ## Story **As a** 没有激活行程（或想从零规划）的用户 **I want** Agent 用自然语言帮我预填现有创建行程弹窗，经我确认后才创建行程 **So that** 我对话就能开始新行程，且城市 / 日期 / 宠物始终由我拍板 ## Business Background US-59 拆分第 2 片（Workflow 创建阶段）：复用现有创建确认弹窗，Agent 只预填不代确认，保证创建契约不变。 ## Enhancement & Solution - Agent 通过现有创建行程确认弹窗协助配置城市、起止日期与单只宠物；天数含首尾 1–7；用户确认前不创建持久化行程。 - 取消 / 关闭弹窗不写入；创建后空计划行程激活，Agent 继续编排（方案先预览后写入，衔接 US-77）。 - 存在激活行程时先经明确确认取消激活，且先完成待发送自动保存；保存失败不取消不创建。 - 无宠物 / 信息缺失或无效时询问引导，不生成可确认方案。 ## Acceptance Criteria **AC-1 弹窗预填与确认**：描述城市 / 日期 / 宠物 → 弹窗预填请求确认；确认后经现有流程创建空计划行程并激活；信息缺失 / 无效（天数不在 1–7）→ 询问，不创建。 **AC-2 取消不写入**：取消 / 关闭弹窗 → 不调创建接口，激活行程不变，配置不持久化。 **AC-3 创建后编排**：创建后以该行程继续规划；方案先展示后确认写入；未确认不持久化不触发保存；放弃规划已创建行程保留（可在 Trips 删除）。 **AC-4 激活保护**：有激活行程时说明将取消并请求确认；先完成待发送保存；保存失败不取消激活也不创建；新行程创建后为唯一激活。 **AC-5 无宠物引导**：无任何宠物 → 说明需先创建宠物，不生成可确认方案。 **场景归属（11）**：spec trip-planning-agent R5（Prepare dialog / Cancel dialog / Confirm new trip / Continue planning / Unconfirmed not persisted / Trip remains after abandon / Active trip exists / Pending save before deactivation / No pets / Required info missing）+ R4 No active trip。 ## Priority: Should
