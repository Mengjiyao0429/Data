# How to ensure message ordering with Kafka, WebSocket, and Redis Pub/Sub in a distributed chat system?

## 正文
I'm building a chat system where: Multiple WebSocket servers handle user sessions. All servers consume from the same Kafka topic (same consumer group). Each user is connected to only one WebSocket server. ❗ The Problem If a Kafka message is consumed by a server that doesn't have the user's WebSocket session, the message gets lost. ✅ Current Attempted Solution Each WebSocket server subscribes to its own Redis Pub/Sub channel. If a server receives a Kafka message but doesn’t have the session, → it publishes the message to the appropriate Redis channel of the server that does. ⚠ The New Issue: Message Ordering In group chats: Some users receive messages directly from Kafka, Others receive them through Redis (extra network hop). This causes message ordering issues due to inconsistent delivery latency. ❓ What I'm Looking For What's a production-friendly way to ensure message ordering across all users in this kind of distributed setup? I'm considering: Using a central Kafka consumer that handles all delivery? Using Kafka partitions per room? Routing everything through Redis, even at the cost of delay? Or is there another recommended approach? Any insights or real-world patterns would be appreciated. Thanks in advance!
