# 任务二：AI 应用机会判别与归类

第三届甘肃省大学生数据挖掘挑战赛（本科组）赛题《AI 应用场景的智能挖掘与机会评估系统》。
本文件夹完整保存任务二的目标、方法、所用数据、结果与全部源码，可直接复现。

## 一、任务目标

对**任务一同一批次的 329 条清洗记录**逐条判断是否构成“AI 应用机会”（1/0）并输出 0~1 机会置信度；
对判为机会的记录，依据附件1 标签体系各标注**一个功能类别**与**一个所属行业**。非机会记录同样保留在结果中。

判定依据（赛题四条规则）：

| 维度 | 核心问题 | 本项目做法 |
|---|---|---|
| ① 真实需求 | 是否有明确用户/业务场景与可观察需求信号 | 需求信号词 + 业务场景锚定；新闻体裁与“供给侧资产”衰减 |
| ② AI 是核心 | AI 是否是解决问题的核心手段 | 成熟 AI 能力词（中英双语）；仅出现“AI”字样只给弱证据 |
| ③ 技术可落地 | 能否用现有成熟 AI 能力实现 | 公开 API/SDK、开源预训练模型、轻量适配证据；自研基础模型打折 |
| ④ 排除情形 | 是否属纯科普教程/广告/AI 营销噱头 | 命中即直接判 0 |

置信度 = 0.36·R + 0.26·A + 0.22·F + 0.16·Q，再乘 (1 − 0.35·E)（E 为排除强度），阈值 0.56。
论文中明确其为**规则证据评分**，不是经统计校准的后验概率。

## 二、完成结果

- **result2.csv：329 行，与任务一批次/编号完全对齐，无缺失、无重复、顺序一致。**
- 判为机会 **147 条**（44.7%）：B01 136/248（54.8%）、B02 9/31（29.0%）、B03 2/50（4.0%）。
- 机会置信度区间 [0.5641, 0.9426]，全部落在 0~1；判 1 记录均有一个合法功能类别与一个所属行业（均取自附件1）。
- 人工标注集 191 条（正 60 / 负 131）评估：Accuracy 0.780、Precision 0.607、Recall 0.850、F1 0.708；
  功能类别一致率 68.3%、所属行业一致率 70.0%。
- 连续两次运行 `result2.csv` 逐字节一致（SHA-256 稳定），可复现。

## 四、数据说明（二次处理留痕）

1. **输入未改**：`原始数据/任务一输出/result1.csv` 与任务一仓库中的结果逐行比对完全一致（329 条），
   任务二只做读取，未修改批次号、记录编号、来源、链接等任何字段。
2. **快照不足时补齐正文**：任务一归档的部分快照正文较短（B01 多为标题/描述级，B03 的 CSDN 正文有截断），
   任务二用 `fetch_snapshots.py` 从公开页面回取正文，存放在 `text/`（260 条）。
   判别时若任务一快照可见正文字符数 < 120 且存在补齐正文，则使用补齐正文，并在
   `task2_evidence.jsonl` 的“文本通道”字段标记 `snapshot_enriched`；否则标记 `snapshot`。
   本次 329 条中 192 条使用任务一快照、137 条使用补齐正文，均可溯源。

## 六、如何验证真实性

1. 打开 `结果/result2.csv`，任取一行，其“采集批次号-记录编号”可在 `原始数据/任务一输出/result1.csv` 中找到。
2. 用该行的记录编号在 `正文快照/` 或 `text/` 中找到对应正文，与 `task2_evidence.jsonl` 中的
   “判别文本”“证据关键词”对照，即可核对判 1/0 的依据。
3. 结果中的功能类别、所属行业均能在附件1 的 16 类 / 30 类中找到，无自造标签。
4. 置信度由固定公式（R/A/F/Q 四维加权）计算，同一条记录的置信度可重复得到。

## 七、已知局限（如实说明）

- 开发者技术问答（报错、版本兼容等）与“业务需求”的边界仍有混淆，是误报的主要来源。
- CSDN 部分记录正文未取全（站点反爬返回 521），只能按现有正文判别，会低估该来源的机会率。
- 基础模型/模型系列仓库（如 ASR 模型）按“模型供给面向开发者、不构成终端业务机会”判 0，属口径选择，论文中有说明。
- 行业标签“其他”占比偏高（100/147），这是“证据不足不硬派行业”的主动原则，避免“HTTP header 问题→体育”这类误标。
