# Safely validating AST of LLM-generated PostgreSQL queries in Java to prevent side effects

I am building a Text-to-SQL application where an LLM generates PostgreSQL queries based on natural language. These queries are executed against a database using a strict read-only user. However, as an additional application-level security gateway, I need to validate the generated SQL string in Java before execution.
 My requirements:
 The query must be strictly a single SELECT statement (no multiple statements via ; ).
 The query must not execute functions with side effects (e.g., calling a custom Postgres function that modifies data or exposes sensitive system info).
 What I have tried: I am currently using JSqlParser to parse the SQL and build an Abstract Syntax Tree (AST):
 Java
 import net.sf.jsqlparser.parser.CCJSqlParserUtil;
import net.sf.jsqlparser.statement.Statement;
import net.sf.jsqlparser.statement.select.Select;
public class SqlValidator {
 public boolean isSafeQuery(String sqlString) {
 try {
 // Parses the SQL. Throws JSQLParserException if there are syntax errors 
 // or if CCJSqlParserUtil.parseStatements() should be used for multiple statements.
 Statement stmt = CCJSqlParserUtil.parse(sqlString);
 // Ensure the root statement is strictly a SELECT
 if (!(stmt instanceof Select)) {
 return false;
 }
 // TODO: How to deeply inspect the AST for side-effect functions?
 return true;
 } catch (Exception e) {
 return false; // Reject on parsing failure
 }
 }
}
 My Question: While checking instanceof Select prevents basic UPDATE / DELETE queries, an LLM might hallucinate or be prompt-injected to generate a query like SELECT my_malicious_function(); where the function performs unauthorized actions.
 Using JSqlParser in Java, what is the most robust approach to traverse the AST (e.g., implementing a custom StatementVisitor or ExpressionVisitor ) to inspect all function calls and sub-queries within the SELECT clause and WHERE conditions? Alternatively, for this specific security validation of AI-generated SQL, is Apache Calcite considered a safer choice?
