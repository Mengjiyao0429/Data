# Optimizing a Gaussian penalty function for HSL color compatibility in PyTorch/NumPy

I am currently developing an AI-driven fashion recommendation system, specifically focusing on a "Multi-modal Context-Aware Decision Model." A critical component of my recommendation engine involves calculating aesthetic compatibility between clothing items based on their color properties.
 To achieve this, I convert image features into the HSL (Hue, Saturation, Lightness) color space and apply a Gaussian penalty function to evaluate color harmony. This function penalizes pairs that fall into specific "unharmonious" hue difference ranges according to color theory.
 While my current implementation using NumPy works for individual queries, I need to optimize this logic for large-scale batched inference to support real-time recommendations. Specifically, I am dealing with the circular nature of the hue component (0-360 degrees).
 Here is the core logic I am using:
 import numpy as np
def gaussian_penalty_score(h1, h2, sigma=15.0):
 # h1, h2 are arrays of hue values (0-360)
 hue_diff = np.abs(h1 - h2)
 # Accounting for the circular hue wheel
 hue_diff = np.minimum(hue_diff, 360 - hue_diff)
 # Gaussian scoring
 return np.exp(- (hue_diff ** 2) / (2 * sigma ** 2))
# Example of batched hue values
h1_batch = np.array([10, 50, 350])
h2_batch = np.array([20, 200, 10])
scores = gaussian_penalty_score(h1_batch, h2_batch)
print(f"Aesthetic scores: {scores}")

 Is there a more vectorized or built-in way in NumPy/PyTorch to handle the circular wrap-around of angular data like Hue before applying non-linear functions?
