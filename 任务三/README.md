# 任务三：赛道热点主题聚合

第三届甘肃省大学生数据挖掘挑战赛（本科组）赛题《AI 应用场景的智能挖掘与机会评估系统》。
本文件夹完整保存任务三的目标、方法、所用数据、结果与源码，可直接复现。

> 输入：任务二判为“机会”的 **388 条**记录（跨 B01–B05）。
> 输出：**14 个主题簇**，覆盖全部 388 条机会记录，产出 `result3.csv`（官方 8 列）。

## 一、任务目标

对任务二判为机会的记录做语义级聚类，形成若干主题簇；为每簇提炼一句话主题名称，
统计簇内机会记录数与来源覆盖，列出簇内机会记录编号以便溯源。对应官方列：

`采集批次号, 主题簇编号, 主题簇名称, 功能类别, 所属行业, 簇内机会记录数, 来源覆盖, 簇内机会记录`

## 二、方法

1. **文本向量化**：对每条机会记录的正文（取任务二快照“## 正文”之后内容）做
   字符/词 n-gram 切分——中文取 2–3 字 n-gram 与短词，英文取 ≥3 字符词；
   构建 TF-IDF（`tf=1+log(count)`，`idf=log((N+1)/(df+1))+1`，L2 归一化），
   并对词表做 df 过滤（去掉仅出现 1 次的极罕见词与出现在 >45% 文档的泛词）。
2. **聚类**：余弦距离 KMeans，k-means++ 初始化，固定随机种子 `20261117`；迭代至分配稳定。
3. **簇数选择**：在 k∈{10,12,14,16,18,20} 上计算余弦轮廓系数，取最优 → **k=14**（轮廓系数 0.0199）。
4. **簇标签**：
   - 主题簇名称：簇内平均 TF-IDF 权重最高的中文/技术英文词（最多 2 个），前置功能类别；
   - 功能类别：簇内成员任务二标签的多数票；
   - 所属行业：簇内成员“非其他”标签多数票；若不足，按附件1 行业中文关键词对簇内正文匹配，
     且需显著领先，否则记“其他”（保守口径，不臆断）；
   - 采集批次号：簇内成员占比最高的批次；
   - 来源覆盖：簇内来源网站计数（前 4 个，超出显示“等 N 源”）；
   - 簇内机会记录：`批次-编号` 列表，以 `;` 分隔。

## 六、如何验证

1. `result3.csv` 表头与官方 `附件/result3.csv` 模板一致（8 列，末列为“簇内机会记录”）。
2. 把每行“簇内机会记录”按 `;` 拆开，逐条 `批次-编号` 回查 `任务二/结果/result2.csv`，
   均应为“是否构成机会=1”；14 簇合计 388 条，等于机会集总数，且无重复。
3. 每簇“簇内机会记录数”等于该行记录编号个数。
4. 功能类别、所属行业均取自附件1 的 16 类 / 30 类标签体系，无自造标签。
5. 任意编号可在 `机会快照/` 找到对应正文，核对主题归属。

## 七、已知局限（如实说明）

- **轮廓系数偏低（0.02）**：机会记录以短文本、中英混杂为主，余弦轮廓系数结构性弱，
  主题簇属于“宏观赛道归纳”，不宜当作严格语义分区；这也是短文本聚类的常见现象。
- **功能类别继承任务二**：簇的功能类别是成员标签多数票，任务二若将某条误标，会传递到簇；
  例如“推荐系统”簇较多，部分来自任务二对 recommendation 类关键词的判定。
- **所属行业保守**：多数簇记“其他”，因任务二判为机会的记录中行业证据普遍不足；
  本任务在“其他”时仅用中文关键词做显著领先匹配，不强行派发行业，避免误标。
- **簇数 k=14** 为轮廓系数最优，但主题粒度可用 k 的敏感性分析进一步讨论。
