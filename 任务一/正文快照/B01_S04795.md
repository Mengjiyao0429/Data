# How to handle i18n in a hybrid Next.js app using both /pages and /app directories?

## 正文
I'm currently migrating a large Next.js project from the old /pages directory to the new /app directory (App Router). This migration will likely take a long time (possibly 1–2 years), so for now, I need to maintain both routing systems side by side. In my next.config.js , I'm using the built-in i18n feature like this: i18n: { locales: ['en', 'es', 'fr'], defaultLocale: 'en', localeDetection: false, } This works well with the /pages directory, but it's not supported in the /app directory. From what I understand, the App Router doesn't currently support the i18n field in next.config.js, this is the first warning in terminal after starting the aplication: ⚠ i18n configuration in next.config.js is unsupported in App Router. Learn more about internationalization in App Router: My question is: Is there any hybrid or recommended approach to handle internationalization in a mixed /pages + /app setup? Or am I forced to fall back to static routing like /pages/en, /pages/es, etc., until the migration is complete? Any guidance or best practices for managing i18n during such a transition would be greatly appreciated.
