## 正文
This is probably futile, but I have a scenario where some customers are using older versions of an Excel spreadsheet form in .xls or .xlsm format with ActiveX checkboxes. I've tried to get them to use updated versions of the form, but it's a lost cause, so I'm trying to make it work as is. My company has very strict security which disables .xls and .xlsm macro code by default and also makes it impossible to save or modify a spreadsheet without an Azure security classification, and as far as I know the only way to assign that is to create a new sheet from a template with a classification, and then copy all the cells and checkboxes over from the old sheet (just shp.Copy from oldwst and then newwst.Paste). Unfortunately, when it copies the ActiveX checkboxes over, they are now just pictures of the original ActiveX controls, so my code to read checkbox values can't do anything with them. I can't read the checkbox values from the original sheet because it looks like I can't access ActiveX/OLE properties (shp.OLEFormat.Object.Object.Value) without enabling macros on the original workbook, which I can't do. So does anyone know if there's any way to identify whether an ActiveX checkbox is checked, either before or after it's turned into a picture? Or copy it in such a way that it doesn't get turned into an image? I've looked all over and the only option that seems like even a remote possibility is to try to convert the shape to a chart shape, export the image, and examine the filesize to try to determine if it's an image of a checked or unchecked checkbox, but that is farther than I'm willing to go, and might not even work if there's no size difference.
