# Tab key does not focus buttons and custom elements in Safari macOS

## 正文
I'm working on a WordPress site that uses a Webflow-exported theme. The site needs to pass WCAG 2AA accessibility standards. Everything works correctly in Chrome and Firefox — Tab key moves through all interactive elements and the focus ring is visible. But in Safari on macOS, Tab skips most elements entirely. Environment: WordPress 6.x Webflow-exported theme ( future_of_fashion ) Safari 17+ on macOS Sonoma Tested with pa11y WCAG2AA Non-native interactive elements in the theme (hamburger menu, slider arrows) are marked up like this: <div class="menu-button w-nav-button" role="button" tabindex="0" aria-label="Open navigation menu" aria-expanded="false"> <div class="w-icon-nav-menu" aria-hidden="true"></div> </div> All slider arrows follow the same pattern — role="button" + tabindex="0" . I removed all outline: none / outline: 0 overrides from both the theme stylesheet and Webflow CSS. Current focus styles: a:focus-visible, button:focus-visible, [tabindex]:focus-visible, [role="button"]:focus-visible, .w-nav-button:focus-visible, .w-slider-arrow-left:focus-visible, .w-slider-arrow-right:focus-visible { outline: 3px solid #fff !important; outline-offset: 3px !important; box-shadow: 0 0 0 5px #333 !important; } Focus indicators work correctly in Chrome and Firefox. I've already tried: Removing all outline: none and outline: 0 Adding tabindex="0" and role="button" to all non-native controls Verifying with pa11y — zero WCAG2AA errors Confirming keyboard navigation works correctly in Chrome and Firefox Safari on macOS appears to skip: <button> <div tabindex="0"> [role="button"] unless macOS Keyboard Navigation is enabled in System Settings. Because the element never receives focus, :focus-visible never fires. So this seems to be Safari/macOS keyboard navigation behavior rather than a CSS issue. Is there any reliable CSS or JavaScript solution to make Safari/macOS include all interactive elements in the Tab order without requiring users to change OS/browser accessibility settings? I considered: Replacing all <div role="button"> elements with native <button> elements Adding a JavaScript fallback that manually moves focus on Tab key events But I'm unsure whether either approach is considered correct or reliable from an accessibility standpoint. What is the recommended WCAG-compliant approach here?
