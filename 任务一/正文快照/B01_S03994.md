## 正文
I’m working on a Snowflake-native data quality monitoring project where I detect anomalies and generate explanations using RAG-style workflows. Current stack: Snowflake Snowpark Python Cortex AI / Cortex Search Streamlit in Snowflake SQL-based data quality checks The system currently focuses on: detecting missing values, duplicates, schema drift, freshness delays, and row count anomalies, logging anomaly results in Snowflake, storing historical quality check results, retrieving relevant historical incidents, and generating explanations/recommendations for current anomalies. I’m trying to improve the RAG architecture for anomaly explanation. My current idea is: Store anomaly logs, quality metrics, metadata, and remediation notes in Snowflake. Use Cortex Search / embeddings to retrieve similar historical incidents. Pass the retrieved context to an LLM to generate a grounded explanation. Display the explanation and recommendation in a Streamlit dashboard. My question: For this type of Snowflake-native RAG workflow, is it better to keep retrieval and context management fully inside Snowflake using Cortex Search, or use an external vector database? I’m especially interested in best practices around: storing historical anomaly context, chunking metadata/remediation notes, grounding generated explanations, evaluating answer quality, and keeping the workflow maintainable inside Snowflake. Has anyone implemented a similar RAG-based monitoring or anomaly explanation workflow on Snowflake?
