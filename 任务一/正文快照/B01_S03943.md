## 正文
I am building a document-loading RAG pipeline for HR policy/Q&A use cases. The pipeline loads multiple PDF/DOC files, chunks them, stores embeddings in a vector database, and retrieves relevant chunks for answering user queries. The issue occurs mainly with table-based queries when asked. Even though the information exists inside tables in the documents, the LLM sometimes: returns incomplete lists, misses rows spread across chunks, hallucinates missing entries, or gives partial answers when retrieval is imperfect. Current prompt: table_prompt_template = """ You are an HR assistant. Rules: - If the question asks for a list (members, names, etc.), extract ALL entries from the context - Combine information across chunks if needed - Do NOT return partial lists - Do NOT assume beyond context Context: {context} Question: {question} Answer: """ Current pipeline: PDF/DOC document loading Text chunking Embedding generation Vector search retrieval LLM-based answer generation Constraints: Low latency is important. I want to avoid heavy multi-agent workflows or expensive reranking pipelines unless absolutely necessary. Accuracy for table/list-based queries is more important than conversational quality. I would like to understand the best production-friendly approach to improve table-based query accuracy while minimizing hallucinations and avoiding major latency increases. Specifically: Should tables be extracted and stored separately from normal text chunks? Is structured storage (JSON/row-wise chunks) better for tables than semantic chunking? Would hybrid retrieval (BM25 + vector search) improve completeness for list queries? How do production RAG systems usually handle tabular data reliably?
