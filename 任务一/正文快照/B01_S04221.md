## 正文
I am testing the Milvus text embedding Function module with the Python MilvusClient API. I read the embedding function docs and set up a collection where Milvus generates embeddings from a raw text field. My goal is to insert documents as text, let Milvus call the embedding provider during insert, and then search either with raw text or with a precomputed query vector. My schema has one VARCHAR field for the document text and one vector field where the function stores the generated embedding: from pymilvus import ( MilvusClient, DataType, Function, FunctionType, ) client = MilvusClient( uri=" ) schema = client.create_schema() schema.add_field( field_name="id", datatype=DataType.INT64, is_primary=True, auto_id=False, ) schema.add_field( field_name="document", datatype=DataType.VARCHAR, max_length=9000, ) schema.add_field( field_name="dense", datatype=DataType.FLOAT_VECTOR, dim=1536, ) Then I add a text embedding function. In this example I am using OpenAI, but the same question applies to other embedding providers: text_embedding_function = Function( name="openai_embedding", function_type=FunctionType.TEXTEMBEDDING, input_field_names=["document"], output_field_names=["dense"], params={ "provider": "openai", "model_name": "text-embedding-3-small", }, ) schema.add_function(text_embedding_function) I create the index and collection like this: index_params = client.prepare_index_params() index_params.add_index( field_name="dense", index_type="AUTOINDEX", metric_type="COSINE", ) client.create_collection( collection_name="demo", schema=schema, index_params=index_params, ) For insert, I only pass the raw text field and do not manually pass the dense vector field: client.insert( collection_name="demo", data=[ { "id": 1, "document": "Milvus can generate embeddings from raw text.", }, { "id": 2, "document": "Vector search compares embeddings by similarity.", }, ], ) This matches my understanding from the docs: the Function module should generate the vector for dense automatically from document . For search, raw text queries work like this: text_results = client.search( collection_name="demo", data=[ "How does Milvus generate embeddings?" ], anns_field="dense", limit=3, output_fields=["document"], ) However, in part of my application I already have a precomputed query embedding from the same model. I want to avoid calling the embedding provider again and search with the vector directly: query_vector = [ 0.012, -0.031, 0.044, # ... 1536 values ] vector_results = client.search( collection_name="demo", data=[ query_vector ], anns_field="dense", limit=3, output_fields=["document"], ) I have checked the docs and found that: the Function module embeds only explicitly defined VARCHAR input fields; the generated embedding is stored in the vector field listed in output_field_names ; insert can provide raw text only; search can use raw text so Milvus generates the query embedding automatically; a precomputed query vector can also be passed, as long as its dimension matches the generated vector field. The part I want to confirm is the SDK behavior when both search styles are used against the same collection. When a Milvus collection uses FunctionType.TEXTEMBEDDING , is it valid to use raw text in client.search() in one request and a precomputed vector in another request, as long as both search the same anns_field and the vector dimension matches the function output field?
