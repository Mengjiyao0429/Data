## 正文
I'm using the contentful npm package (version ^11.5.11) in a TypeScript project and querying entries with a match operator on a field (fields.key). The query works correctly and returns expected results, but TypeScript throws the following warning: Object literal may only specify known properties, and '"fields.key"' does not exist in type 'EntriesQueries<QuestionAndAnswerFields, undefined>'.ts(2353) Here’s a simplified version of my code: import { createClient, type EntrySkeletonType } from "contentful"; const client = createClient({ space, accessToken, host }); export interface QuestionAndAnswerFields extends EntrySkeletonType { fields: { key: string; order: string; question: Document; answer: Document; }; contentTypeId: string; } const response = await client.getEntries<QuestionAndAnswerFields>({ content_type: "questionAndAnswer", "fields.key[match]": `helpcenter.${partnerId}.*`, // TS warning here locale, }); The query works fine at runtime, but I’d like to get rid of the TypeScript warning. Is there a recommended way to pass custom query parameters like "fields.key[match]" without breaking the type system? Or should I be casting something to bypass this safely? Any help would be appreciated! I used the "fields.key[match]" filter inside the getEntries query expecting to retrieve entries where the key matches a certain pattern (which it does successfully). I expected TypeScript to accept the query since it's a valid Contentful API parameter, but instead, I got a type error saying the property doesn't exist on EntriesQueries.
