## 正文
Trying to install Haskell / ghci for the first time, though I intend to try it under a MSYS2 bash shell on Windows 10. Anyways, I was somewhat surprised to experience that it is very difficult to specify a custom location for everything Haskell related. So, recommends using "ghcup or Stack" to install, and says "On 64-bit Windows, the easiest way to install Stack directly (rather than use GHCup) is to download and install the Windows installer ." - so I decided to go with Stack, and got stack-2.13.1-windows-x86_64-installer.exe . Upon running the installer, it wanted to use C:\Users\[USER]\AppData\Roaming\local\bin to install, but for one I don't really like digging in AppData (and I also might run out of space on C:, so might have to choose a different drive for this install) - so to begin with, I replaced the installation path to C:\HaskellStack , and let the installer finish. Note that while the installer does indeed change the Windows 10 System/Advanced/Environment Variables/User variables for [USER]: Path, somehow that did not propagate to my existing MSYS2 bash shell, and since I did not want to reboot the PC, below I'm using a full path to call stack.exe . I kind of thought that I'd get a full install (which includes ghc and whatever else is needed), but no - after the installer finishes, at start, there are only two files in the installation directory: $ ls /c/HaskellStack/ stack.exe* uninstall-stack.exe* OK, so I thought, I'd try running ghci first - and I got this: $ /c/HaskellStack/stack.exe ghci Writing the configuration file for the implicit global project to: C:\Users\[USER]\AppData\Roaming\stack\global-project\stack.yaml. Note: You can change the snapshot resolver field there. Using the latest snapshot lts-22.5. ... Oh, wait - NO, I do not want anything to do with C:\Users\[USER]\AppData - why is it there? So, I found Changing Stack's storage directory on Windows and from there, Option for location of programs installed by setup · Issue #2067 · commercialhaskell/stack Ok, so did a full uninstall (of "Haskell Stack" under Control Panel\All Control Panel Items\Programs and Features), then reinstalled stack installer; and this time I started with: $ /c/HaskellStack/stack.exe --stack-root The option `--stack-root` expects an argument. $ /c/HaskellStack/stack.exe path --stack-root Writing the configuration file for the implicit global project to: C:\Users\[USER]\AppData\Roaming\stack\global-project\stack.yaml. Note: You can change the snapshot resolver field there. Using the latest snapshot lts-22.5. msys2-20230526: download has begun^C Oh, damn it - so even if I just want to print out the "stack-root" path, stack still starts with a download into C:\Users\[USER]\AppData ; ughh, how irritating. Ok, so did a full uninstall (of "Haskell Stack" under Control Panel\All Control Panel Items\Programs and Features), then reinstalled stack installer; and this time I started with: $ /c/HaskellStack/stack.exe --stack-root 'C:\HaskellStack' Missing: COMMAND|FILE Right, so I cannot "just" set "stack-root" path in this way... So finally I decided to set STACK_ROOT as a (temporary) environment variable, and then call path --stack-root to simply print out the "stack-root" path; this time I wasn't really surprised that this started up a download: $ STACK_ROOT='C:\HaskellStack' /c/HaskellStack/stack.exe path --stack-root Writing the configuration file for the implicit global project to: C:\HaskellStack\global-project\stack.yaml.
