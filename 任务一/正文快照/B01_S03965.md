# Localization works locally but not in Docker container (ASP.NET Core)

## 正文
I'm working on an ASP.NET Core project with localization support. Everything works as expected when running the app locally on Windows (e.g., using dotnet run ). However, after building the project into a Docker image (Linux-based) and running the container, localization stops working. Instead of returning the translated strings, it falls back to the resource keys (e.g., "ITEM_NOT_FOUND" instead of the localized value "Items with id {0} is not found!" ). Here is the localization configuration in my Program.cs : services.AddLocalization(options => options.ResourcesPath = "Resources"); services.Configure<RequestLocalizationOptions>(options => { var supportedCultures = new List<CultureInfo> { new("fr"), new("fr-FR"), new("en"), new("en-US") }; options.DefaultRequestCulture = new RequestCulture("en"); options.SupportedCultures = supportedCultures; options.SupportedUICultures = supportedCultures; }); Has anyone experienced this issue before when running ASP.NET Core in Docker? If so, what steps did you take to fix it? I'm using ASP.NET Core 8.0 What I suspect: The issue might be caused by differences between Windows (dev machine) and Linux (Docker container), especially related to culture fallback behavior or missing globalization data. What I tried: I tried to re-organize the middleware, Place UseRequestLocalization before MapControllers and MapHealthChecks("/health") in the Program.cs follow this reference but it seems doesn't work.
