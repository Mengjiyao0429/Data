My setup: Many users, each uploading multiple documents Documents have metadata with userId Need to isolate user documents by user and filter by userId Using LangChain for retrieval with filters Current table structure: CREATE TABLE document_vector ( id BIGSERIAL, content TEXT, metadata JSONB, embedding VECTOR(1536) ); What's the best approach to optimize for scalability and query performance? Create a new table per user? Add a user_id column and partition the table? Index the metadata->>'userId'? Another approach? Looking for a solution that scales well and maintains good performance for vector similarity searches with user-specific filters. Appreciate your help! I tried implementing hash partitioning on the document_vector table based on the userId stored in the metadata JSONB field but not sure if this is the right approach. CREATE TABLE document_vector ( id BIGSERIAL, content TEXT, metadata JSONB, embedding VECTOR(1536) ) PARTITION BY HASH ((metadata->>'userId'));
