# Xdebug trigger-based mode selection works in CLI, not in Apache

- 发布时间：2025-04-16

## 正文
I have trouble getting xdebug (3.4.2) to work in Apache. Here is my xdebug.ini file, which is symlinked from both /etc/php/8.2/{apache2,cli}/conf.d/ . zend_extension=xdebug.so [xdebug] xdebug.log_level=0 #xdebug.mode=debug xdebug.start_with_request=trigger xdebug.discover_client_host=true xdebug.idekey="phpstorm" xdebug.output_dir="/xdebug-profiler" xdebug.profiler_output_name="cachegrind.out.%p" xdebug.profiler_append=1 xdebug.trace_output_name="trace.%p.xt" xdebug.log=/xdebug-profiler/xdebug.log xdebug.log_level=10 Note: /xdebug-profiler is owned by my user, with the group being www-data , writable by both. In my vhost's root, I created this simple file: <?php xdebug_info(); phpinfo(); If I run php from the CLI: XDEBUG_TRIGGER=1 XDEBUG_MODE=debug php xdebugtest.php | grep 'xdebug\.mode' I can debug it step by step in my IDE and the output is, as expected: xdebug.mode (through XDEBUG_MODE) => debug => develop The second value being the master (default = develop ) value, being overridden by the first (local = debug ) value. Now switching to my browser, accessing the same file through apache, having tried (at the same time) all 3 methods of triggering: cookies (checked in the browser's request inspector): XDEBUG_TRIGGER=1 ;XDEBUG_MODE=debug HTTP parameters: ?XDEBUG_TRIGGER=1&XDEBUG_MODE=debug environment variables: SetEnv XDEBUG_TRIGGER 1 and SetEnv XDEBUG_MODE debug in my virtual host Unfortunately, none of those seem to do anything: my IDE doesn't "see" a connection for step-by-step debugging the output of xdebug_info() tells me I'm still in 'develop' mode. In case it's relevant, I've recently upgraded to Ubuntu 24, but since I didn't have the same xdebug.conf before, I have no idea whether it plays any role at all. I did notice a discrepancy in phpinfo() between PHP "Version (run time) = 8.2.28" and "Version (compile time) = 8.2.27". No idea why and how to solve that (or even if it needs solving). After prompting an AI chatbot, I also checked that mod_env and mod_headers were enabled in Apache. They were. What I didn't try: same test on a different machine (which I don't have at the moment) same test on a different virtualhost (I didn't use 000-default, but the one I'm using is pretty basic, no strange modules, no weird options).
