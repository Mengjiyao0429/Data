We are building an experimental system that will do live call transcription and sentiment analysis. We are locked into the existing UCM, which is a GrandStream system. Our plan for live call transcription is to use the Grandstream web socket service to push a notification to our process handler whenever a call is received or placed. This will trigger a call barge that will add an extension mapped to a server running a softphone to the call. It will also trigger the call transcription service to listen to the audio stream. So far so good. The problem is how to take the audio stream coming into the softphone and convert it to something that can be captured by our audio transcription service (likely running on a different system). Our plan is to map multiple extensions to the same server, with separate softphone instances listening to each extension IP/port combo. One solution I have in mind goes something like this: Softphone receives audio packets --> ( here be dragons ) --> call is streamed media server --> Remote call transcription service connects to media server and begins transcription process.
