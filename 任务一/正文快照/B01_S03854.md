## 正文
I'm trying to connect a BigQuery table containing property listings (originally from an Excel/CSV file) to a Vertex AI Agent Builder / Dialogflow CX agent using a Structured Data Store. My goal is to allow the agent to look up property details based on a unique property ID. My Setup: Agent: Located in europe-west4. Data Source: BigQuery table in the same project. The table was created from a CSV upload (UTF-8, semicolon delimiter, handles quoted newlines and escaped quotes). BigQuery Schema: Includes columns like id (originally INT64, now STRING after recreating the table), address (STRING), city (STRING), description (STRING), price (FLOAT64), etc. Data Store: Created in the eu multi-region (as required for the europe-west4 agent). Source is the BigQuery table. The Problem: When configuring the Data Store schema (either when creating a new one or editing an existing one), I cannot set the id column as the unique ID Key Property. On the "Review schema and assign key properties" screen, the "Key properties" section (where the ID and Content dropdowns should be) seems to be missing or unusable. I cannot select my id column for the ID mapping. This happens even when creating a brand new data store from the BigQuery table where id is confirmed to be STRING. The id column does appear in the main "Fields" list below, and I can successfully toggle Indexable, Searchable, and Retrievable for it. Resulting Agent Behavior: Because the ID Key Property isn't correctly mapped (it might be defaulting to description or nothing): When I give the agent a valid property ID (e.g., 112970), the agent's debug log shows it correctly calls the linked Data Store tool (action: query^MyDataStoreTool). However, the tool's output is empty (output: answer: '', snippets: []). The agent then reports Retrieved examples: [id_not_set(display_name_not_set), ...], indicating the search failed. Interestingly, sometimes searching by description does return some results, suggesting the data store is partially indexed and searchable on other fields, just not correctly on the ID. What I've Tried: Confirmed the id exists in the BigQuery table using SELECT * ... WHERE id = '112970'. Ensured the id column in BigQuery is STRING. Created the Data Store in the correct eu multi-region. Verified Data Store indexing status shows "Completed". Confirmed id column is marked Searchable and Retrievable in the Data Store schema field list. Tried hard browser refresh, incognito mode, and different browsers - the ID Key Property dropdown remains missing/unusable. Explicitly instructed the agent in its prompts to use the specific Data Store tool for ID lookups. Question: Why might the ID Key Property dropdown be missing or unusable in the Data Store schema configuration UI, even during creation? Is this a known bug, a permission issue I'm missing, or specific to BigQuery sources? Is there a reliable way to set or update the ID Key Property mapping using gcloud commands or the API, given the UI failure? (If so, what would the command/JSON structure look like?) Any help would be appreciated!
