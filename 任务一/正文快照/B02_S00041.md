摘要：2026年9月30日，60集闽南语竖屏短剧《等你平安归来》获第四届上海国际AIGC创新大赛AI短剧赛道“最佳短剧剧本奖”（大赛1108件有效作品、106件终评，五项压轴奖之一）。本文不讲评测、不挑文档，直接给一份可以照着抄的执行SOP：咱做落地的，怎么用阿里云函数计算 FC + 百炼大模型 + ComfyUI 渲染 + 对象存储 OSS 搭一条可复用、可弹性扩缩的 AI 短剧生产管线，解决从剧本结构化 JSON、到 AnimateDiff 动画渲染、到方言配音校准、到 60 集资产治理、到政企文旅复用的全链路问题。方言这条线毋通想走捷径，声调建模这关绕不过去，但工程层该让云扛的就交给云。
一、【落地起点】为什么选模块化云栈，不搞一锅端
先说清楚业务痛点，再讲选型逻辑。
我们这个项目的核心卡点有三个：
方言不是换个口音就能做：闽南语 7-8 个声调承担辨义，通用 TTS 直接套方言口音会“串味”，这不是前端界面问题，是音素层建模问题，必须能接垂直引擎。
60 集体量不是单次生成：跨集角色一致性、批量渲染调度、版本回溯，这些是工程问题，不是模型问题。
成本要可控：GPU 实例长驻跑一个月，费用够再做两部戏，必须弹性伸缩。
所以选型逻辑很直接——模块化解耦，让每一层只干自己最擅长的事：
算力调度交给弹性基础设施
通用文本/语音生成交给大模型平台
图像/动画渲染交给开源工作流引擎
资产存管交给对象存储
方言垂直能力通过 API 接入自研引擎，不绑死在某一家模型上
这也是为什么最终落在函数计算 FC + 百炼 + ComfyUI + OSS这套栈：层间边界清晰，每一层都能独立替换，不会因为某一个环节能力不够整套推倒重来。
二、【架构设计与管线搭建】三层四域，端到端打通
2.1 整体架构分层
层级 组件 职责 关键配置
调度层 函数计算 FC 承载ComfyUI与WebUI两个函数服务，弹性拉起GPU实例，任务队列调度 FC 3.0，分别部署ComfyUI渲染函数与WebUI管理控制台；服务角色授权打通OSS读写权限
模型层 阿里云百炼 剧本生成、通用TTS配音、字幕生成、文本结构化输出 配置API-KEY，模型按场景选；剧本输出强制JSON Schema
渲染层 ComfyUI（FC部署） 角色LoRA加载、AnimateDiff动画生成、关键帧渲染、风格一致性控制 预置AnimateDiff工作流模板，LoRA按项目挂载
存储层 对象存储 OSS 剧本/素材/成片/审计四类资产归档，版本控制 Bucket地域与FC/百炼同区，读写权限私有，开启版本控制
增强层 海峡姬音方言AI引擎 闽南语音素层声调建模、声纹适配、母语者校准API 作为垂直能力通过HTTP API接入，不侵入主链路
2.2 百炼Prompt设计：强制输出结构化剧本JSON
剧本生成环节最容易出问题的地方，是大模型输出自由文本，下游没法直接喂给渲染节点。所以Prompt必须强制JSON结构，用Schema约束输出。
