## 正文
I have a requirement to generate parquet file with a column defined as follows: String List element UTF-8 byte-array STRING I am using parquet.net Nuget in code to produce the file through class serialization. When I defined this in the code as property public class A { string[] STRING {get; set;} } Resulting column is showing 2 levels down. String List group list element UTF-8 byte-array STRING This seems to correspond with latest version of the standard that recommends using 3-level structures to avoid ambiguity. Unfortunately, as we are interfacing with external legacy system I'm unable to change the format. Adding the Parquet legacy attribute results in the property being rendered as Repeatable. When reviewing it on one of the other parquet-viewers it reveals the schema defined in JSON as follows: "GroupType": { "field_info": { "name": "String", "repetition": "Required", "id": null }, "logical_type": "List", "converted_type": "List", "fields": [ { "GroupType" : { "field_info": { "name": "list", "repetition": "Repeated", "id": null }, "logical_type": null, "converted_type": null, "fields": [ { "PrimitiveType": { "field_info": { "name": "array", "repetition": "Required", "id": null }, "logical_type": "String", "converted_type": "Utf-8", "physical_type": "ByteArray" } }, ] } }, ] } I would like to achieve the following schema: "Group_type": { "field_info": { "name": "String", "repetition": "Optional", "id": null }, "logical_type": "List", "converted_type": "List", "fields": [ { "PrimitiveType": { "field_info": { "name": "array", "repetition": "Repeated", "id": null }, "logical_type": "String", "converted_type": "Utf-8", "physical_type": "ByteArray" } } ] } var listOfA =[new A{String=["item1"]}]; var schema = ParquetSerializer.SerializeAsync<A>(listOfA).GetAwaiter().GetResults(); Changing the property from array to List<string> didn't achieve any results as it seems the library handles those as IEnumerable. What would be the correct definition of the expected property in c#?
