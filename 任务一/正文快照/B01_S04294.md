## 正文
I'm trying a proof of concept where I'd like to provide for a pretty standard business intelligence use case where biz dev folks can ask arbitrary natural language questions of a client database. It seemed like an AWS Bedrock Knowledge Base would fit the bill, with a Data Source consisting of a CSV file in S3, along with a Foundation Model to do the natural language processing: the Retrieval-Augmented Generation use case. It won't have direct access to the db itself, so that rules out the Redshift-based 'Knowledge Base with structured data store', but posting CSV snapshots to S3 will be feasible, as the CSV would only have around 10k records, a couple dozen columns, and in the transfer any PII can be anonymized. Definitely not a big data problem, yet it'd be valuable, and seemingly tailor-made for the RAG use case. Right? After setting up a first pass at it, though, it often very confidently returns answers to the most basic questions that are completely wrong. Comedically wrong. So trust in asking more complex questions will be nil. I know that there are a lot of options and tweaks, though I've found very little guidance on where the correct path is. The net net seems to be just try everything and see what works! Well, that's a lot of spaghetti to throw at the wall.
