## 正文
We want to migrate an Oracle database with BLOB type for some columns to a Postgres database and to have our Spring Boot application working with it (we use JPA and hibernate). I saw that BLOB from Oracle is equivalent to BYTEA in Postgres but I also saw some discussions on the Internet talking about the fact that the dialect considers OID type instead of BYTEA for blobs: public class PostgreSQLDialect extends Dialect { ... protected String columnType(int sqlTypeCode) { ... case BLOB: case CLOB: case NCLOB: // use oid as the blob/clob type on Postgres because // the JDBC driver doesn't allow using bytea/text via // LOB APIs return "oid"; // use bytea as the "long" binary type (that there is no // real VARBINARY type in Postgres, so we always use this) case BINARY: case VARBINARY: case LONG32VARBINARY: return "bytea"; ... } } The comment indicates why oid is used by the dialect. So it seems that oid should be used. Also, I saw that some people can have errors when using BYTEA: java.sql.SQLException: ERROR: column "xxxxx" is of type bytea but expression is of type oid The code for my entity uses java.sql.Blob: (name = "DOCUMENT") private Blob document; I also saw that when removing oid row from a table, large object itself stays in the DB if you use Hibernate and this is not what we want (we want to delete the Blob and not only the oid referencing the blob on the file system). This discussion recommends to use BYTEA if the type was BLOB in Oracle: So I am lost. What should I use to work with blobs for column type without problem with Spring Boot? BYTEA or OID? And how to delete correctly the blob if OID type is used?
