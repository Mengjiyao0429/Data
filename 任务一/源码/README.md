# AI 应用场景的智能挖掘与机会评估系统 —— 任务一说明

第三届甘肃省大学生数据挖掘挑战赛（本科组）。系统采用 Python 实现，规划为
FastAPI 后端 + 原生 HTML/JS 前端，当前已完成**任务一：多源数据采集与清洗**。

## 三、产出文件与字段

- `data/B01/results/result1.csv`（utf-8-sig，Excel 可直接打开），表头对齐官方示例：
  `采集批次号 | 记录编号 | 来源网站名称 | 来源链接 | 内容 | 发布时间 | 热度指标（如浏览数、点赞数、讨论数等）`
- `data/B01/text/`：每条记录清洗后正文快照，文件名按批次独立编号——
  `B01_S00001.md … B01_S00248.md`、`B02_S00001.md … B02_S00031.md`、
  `B03_S00001.md … B03_S00050.md`；result1 的“内容”列填写对应快照相对路径，
  保证可溯源。记录编号在各批次内从 S00001 开始，靠“采集批次号 + 记录编号”联合唯一。
- `data/collected/`：原始采集 JSON（含 API/RSS、浏览器采集与 CSDN 的原始字段）。

## 四、如何复现

```bash
pip install -r requirements.txt
python run_task1.py B01        # API/RSS 六源采集
python merge_task1.py B01      # 并入浏览器采集的国内源
python rebuild_batches.py      # 按 B01/B02/B03 重组（SO 取 top100、CSDN 取 top50）
```

核心模块：`app/pipeline/collector.py`（采集）、`app/pipeline/cleaner.py`（清洗）、
`app/pipeline/dedup.py`（精确 MD5 + 字符 shingle Jaccard 近似去重）、
`merge_task1.py`（浏览器记录转换与正文剥离）、`rebuild_batches.py`（批次重组）。

## 五、如何自行验证真实性

1. 用浏览器打开 result1 中任意“来源链接”，页面真实存在且标题/正文与快照一致。
2. 已实测：CSDN 文章在浏览器可正常打开，正文关键句与快照一致、热度为页面真实数值；
   36氪、阿里云、腾讯、医药促进会、GitHub 同样可在浏览器打开并核对。
3. 每条记录的星标、点赞、收藏、评论、浏览量均为接口或页面返回的真实数值，
   未人工编造。
4. 反爬说明：Stack Overflow 与 CSDN 对脚本直接 GET 分别返回 403 / 521（Cloudflare
   及站点频率防护），**真实浏览器可正常访问**；这是反爬拦截，不是链接失效。
   验证时请用浏览器打开，勿用脚本批量请求。

## 六、采集合规说明

仅采集公开信息并注明出处；优先使用官方公开 API/RSS，浏览器渲染仅做正常浏览式访问
（不破解反爬、不高频、不采集个人信息、不规避访问控制），请求间设置延迟，
不对目标站点造成异常访问压力。

### 实测暂不可用/受限的源（如实披露）

- V2EX：本地网络连接超时；Papers with Code：本地网络无响应；
  Semantic Scholar：无 API Key 时持续 429 限流。
- 机器之心：原 RSS 地址已下线；新浪 RSS 服务已停更（最新条目停留在 2018 年）。
- 讯飞开放平台、WPS：仅有产品/解决方案页，无带发布时间的公开内容流，
  故不作为任务一内容采集源。
