一、闽南语竖屏短剧《等你平安归来》为什么是这套方案
咱做落地的，最怕听到一句话：「这个 AI 不是能一键生成吗？」
60 集竖屏短剧，每集 3 到 5 分钟，全闽南语对白，六组固定人物，跨集连续叙事。这不是一个 demo，是一条要按时交付、要过审、要能复用的生产线。通用方案在这里会撞上三堵墙：
方言墙：通用 TTS 能读闽南语的字，但念不对七到八个声调，气口全乱，母语者一听就出戏。
一致性墙：第 1 集和第 47 集的同一个角色，脸、服装、光位必须对得上，否则观众直接跳戏。
成本墙：60 集批量渲染，GPU 一旦常驻，账单比制作费还吓人。
所以咱选的不是「一个能生成视频的工具」，而是一套可解耦、可替换、可审计的模块化底座：剧本层用百炼大模型产出结构化 JSON，渲染层用 ComfyUI + AnimateDiff 跑在函数计算 FC 的弹性 GPU 上，资产层用 OSS 做四域分仓，方言语音层外挂垂直引擎补声调。哪一环不行，换哪一环，管线不动。
二、架构设计与管线搭建
2.1 整体分层
层级 组件 职责 关键约束
创意层 百炼大模型 剧本、分镜、对白生成，输出结构化 JSON Schema 强校验，字段缺失即拒收
编排层 函数计算 FC 任务分发、状态机、重试、回调 单次执行超时与幂等键必须设计
渲染层 ComfyUI + AnimateDiff 图生视频、镜头合成 LoRA 与种子随任务下发
语音层 百炼 TTS + 垂直方言引擎 基线配音 + 声调修正 母语者校准环节不可省
资产层 OSS 四域分仓、版本基线、审计留痕 路径即契约，禁止随手建目录
2.2 百炼：让剧本输出「可被程序消费」的 JSON
很多人卡在这一步——让大模型写剧本，它给你一篇散文。咱要的是能被下游直接解析的结构。做法是把 Prompt 拆成「角色卡 + 分集任务 + 输出契约」三段，并在系统提示里钉死 Schema：

 "time": "夜",
 "characters": ["A_MOTHER", "B_DAUGHTER"],
 "shots": [
 {
 "shot_id": "ep12_s01_sh01",
 "camera": "中景",
 "duration_sec": 4,

 "dialogue": {

}
三个工程要点：
字段级校验：FC 侧收到 JSON 后先跑一遍 Schema 校验，shot_id 缺失、duration_sec 超限直接打回重生成，不让脏数据流进渲染层。
角色 ID 化：对白里只出现 A_MOTHER 这类角色 ID，不出现人名。人名在角色卡里映射，改名字不用重跑全剧。
Prompt 与渲染解耦：image_prompt 由百炼生成，但 LoRA 名与种子由编排层注入，保证模型换版本时画面基线不漂。
