## 正文
I’m maintaining a large C++ project that uses Eigen for solving large sparse systems ( ) and other dense operations. What changed I upgraded from Eigen 3.4.1 to Eigen 5.0.0 . After the upgrade, one specific configuration no longer builds: Debug + AVX-512: links fine Release/Debug + AVX or AVX2: links fine (≤ ~2 min) Eigen 3.4.1 (same project/settings): links fine Release + AVX-512 + /GL + /LTCG : link step consumes huge memory and eventually fails with OOM (after ~90 minutes) I compile with full MKL support enabled : EIGEN_USE_MKL_ALL Symptoms In the failing configuration (Release + AVX-512 + /GL + /LTCG), the linker starts consuming a very large amount of Private Bytes and eventually crashes with out-of-memory. If I disable optimization (Remove /GL and /LTCG ), the build “get stuck” while compiling one translation unit (may be doing extremely expensive optimization/inlining). What I traced it to It seems correlated with using Eigen::SparseLU . If I remove the code path calling SparseLU , it builds fine. Using Visual Studio Build Insights, the compiler appears to spend a very long time inlining around internal kernels, demangling shows especially: public: void __cdecl Eigen::internal::gemm_class<double,1>::compute_kern<24,8>(void) public: void __cdecl Eigen::internal::triSolve<double,0,0,1,1>(double*, double*, __int64, __int64, __int64, __int64) Workarounds that fix it If I redefine EIGEN_STRONG_INLINE to plain inline (instead of __forceinline ), the build succeeds. Defining EIGEN_DONT_VECTORIZE also avoids the issue. Constraint: minimal repro difficulty I currently cannot reproduce the issue with a small standalone project, so it may require “project-scale” template pressure to trigger. Questions Has anyone seen MSVC Release + AVX-512 blow up (compile or link memory) with Eigen 5.x, especially around SparseLU / gemm_class / triSolve ? Are there recommended Eigen-side mitigations besides disabling vectorization or globally weakening inlining? Are there MSVC/LTCG options that help here (e.g. controlling inlining/codegen), or known limitations for AVX-512 + LTCG? Environment / build details OS: Windows (x64) Compiler: MSVC (Visual Studio 17.14.23, c++20) Eigen: 3.4.1 OK → 5.0.0 fails (5.0.1 also fails) MKL: enabled ( EIGEN_USE_MKL_ALL ) Version: 2025.1.0.798 (Same behavior with 2025.3.1.9) Failing configuration: Release x64, AVX-512 /arch:AVX512 , /O2 /GL and link /LTCG Other configs OK: Debug AVX-512; Release/Debug AVX/AVX2
