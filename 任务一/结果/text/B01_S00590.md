# Ask HN: How do you track bugs filed against an in-review feature?

- 来源：Hacker News
- 链接：https://news.ycombinator.com/item?id=23575761
- 发布时间：2020-06-19
- 热度：点赞2、评论1

## 正文
I've built software project management software and still haven't seen a great solution for this. Here's the scenario: 1. You wrote a new feature and opened a PR 2. Your UAT/QA people test it 3. They find bugs / issues to address Where do they put those issues? Some options: 1. They add them as comments on the original feature ticket. This seems like a bad idea because comments don't have a state (needs doing, done, won't do) so it's hard to track how much work is left to do. 2. They add them as tasks on the original feature ticket. Not terrible but hard to record repro steps (with images etc if necessary) as a task 3. They add them as NEW issues and link them to the original issue. Still not a great option: if linking doesn't happen, the new issues are orphaned. Plus it's a bunch of work to relate issues (in some issue trackers). I default to #3 solution but wanted to see if there were other approaches I hadn't considered. My goals are: 1. Capture bugs with repro steps and urls/pictures if necessary 2. Be able to triage them (will do / won't do), assign them, and have state (open, in progress, closed, etc) to see how many are left to ship the original feature 3. Do it with as little pain as possible. How do you solve this problem?
