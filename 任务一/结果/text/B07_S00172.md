# Ask HN: Porting HPC Software to ARM

- 发布时间：2025-01-08

## 正文
Hello all, I am in the process of porting some HPC software from x86 to ARM. Specifically I am looking at building Hybrid AI-HPC models and targeting Nvidia’s GH200 due to its heterogeneous architecture. My background is as an ML engineer, and I am contributing to this project as a part time hobby. I have a few questions that I wanted to get some help with. 1. Is Nvidia’s Xavier lineup of SOC’s a similar enough architecture to develop off of? Cloud development costs are starting to get expensive, and I would like to buy some hardware as a fixed cost while I am doing development, then doing a hero run on rented compute. But I want to make sure I have a close approximation of a GH200’s underlying CPU-GPU interconnect so I can correctly profile my code. I understand the Xavier and GH200 are vastly different products, and I am just looking for a scaled down version of the hardware. 2. Does anyone know of a good way to profile code on an ARM server/machine? I was doing some benchmarks and the GH200 that I rented was preforming only twice as fast than my x86 desktop. This was significantly slower than I expected. I hypothesize this is due to x86 being the target architecture so optimizations where made that don’t transfer. My goal is not to due a full rewrite (this code base is probably 100k’s of code), but tweak compiler settings and dependencies to maximize performance. As well as understand where the bottlenecks are for future reference. 3. The code base is written in Fortran, are there any language specific things I need to be aware of? Thanks for any and all help.
