## 正文
I am working on developing an application on an air-gapped system, and would like to be able to take changes up to an internet-connected network for distribution. There is also the possibility that changes made on the internet-connected system would need to be taken back down to the air-gapped system... ... which would normally be tri easy with git bundle , however there are some complications with how I need to have the repos set up. On the air-gapped system, the repo consists of several directories, each with distinct code (meaning each directory contains code that largely doesn't interact with code in other directories). Each branch of the repo corresponds to work done in only one directory, which is then merged back to main so that main contains the most up-to-date code across all directories. The problem is that there are sharing concerns between directories in the repo. On the air-gapped network, all directories are in a single repo because I develop them all in parallel and managing multiple (10+) separate repos would be challenging. However, when I go to distribute the code, I only want to make the code from a single directory available on the internet-connected system in its own repo. So I can't use git bundle directly since even a bundle from an individual branch would still contain all of the other directories, and patches would be looking for directories that aren't there. From my own searching it looks like git filter-repo is what I'm looking for, but as far as I can tell it would only really help in one direction. I can separate out a single directory (with its associated history) into its own repo to bring up, but I'm unsure how changes made on the internet-connected system could be brought back down given the dissimilar histories. Any help or recommendations you might have would be much appreciated. I know this is kind of a cursed setup, but it is the system I have inherited and am trying to make the best of.
