用FC+百炼+ComfyUI把60集方言短剧从0到1跑通
台青廖昌威凭60集闽南语短剧《等你平安归来》拿下第四届上海国际AIGC创新大赛"最佳短剧剧本奖"。真正的工程问题，不是"AI 能不能生成"，而是"60集、全方言、多环节，怎么在一条管线里稳定跑完、还能交付、还能复用"。本文是这套 AIGC 管线的落地执行方案。
咱做落地的都明白：一部短剧能不能交付，比能不能生成更考验工程。下面这套东西，是我们把"想法"推到"成片"时逐条踩出来的做法。
闽南语短剧《等你平安归来》为什么选阿里云这套方案
一句话结论：因为这套组合能模块化解耦，把"创作、渲染、方言、存储"拆开各自演进，互不卡死。
先看业务痛点：通用方案搞不定方言——闽南语有7到8个声调、普通话只有4个，声调承载词义（语言学常识）；通用大模型大多只能识别方言文字，很难地道输出方言语音，更无法演唱方言歌曲（据海峡姬音团队公开路演披露）。如果整条链路耦合在某个通用方案里，方言这一环会拖死全部。
所以选型原则是能解耦才选：函数计算（FC）管执行与弹性、百炼大模型管内容生成、ComfyUI 管渲染、OSS 管资产，方言配音单独接"海峡姬音"这类垂直引擎补声调。模块各自演进，一坏不坏全部。
【架构设计与管线搭建】FC＋百炼＋ComfyUI＋OSS
一句话结论：四个组件各管一段，靠任务编排把它们串成一条可回滚的生产流水线。
百炼：Prompt → 结构化剧本 JSON
剧本不是让模型自由发挥，而是产出结构化 JSON，机器可直接消费：
用 Prompt 约束输出 JSON Schema：剧集、场次、镜头、角色、台词、情感、道具、地点、音轨引用。
每集"核心情感点＋信息增量＋共情锚点＋五感设计"落入字段（复用获奖短剧《等你平安歸來》的剧本工程化方法，据项目文档）。
输出先入 staging，再由人抽检，符合再进 render 队列。
FC：部署 ComfyUI 节点跑 AnimateDiff
用 FC 包一层 ComfyUI 节点，把"文生图→图生视频/动画"封装成可调用的函数，按镜头触发。
渲染任务走事件队列，FC 按需弹性执行，避免常驻 GPU 空烧。
每镜头渲染锁定LoRA 与随机种子，保证同一角色/场景跨集稳定。
OSS：资产目录规划
资产按"创作域／视觉域／音频域／交付域"四域规划，桶内分目录：
 oss://str-everyone-safety/
 ├── source/ # 创作域：剧本JSON、分镜、台词、原声素材
 ├── staging/ # 中间产物：草稿图、临时音轨
 ├── render/ # 视觉域+音频域：分集分镜头渲染输出、方言TTS轨
 ├── release/ # 交付域：RC→Release 基线成片、字幕、海报
 └── archive/ # 审计归档：交付台账、版本记录、母语校准轨
