## 正文
I’m building a browser tool that shows big PDF blueprints and lets you measure, with a “Set Scale → Calibrate from two points” flow (click two points on the sheet, enter the real-world distance, and we store that scale for the page), but when I start calibration the PDF sometimes blanks/reloads and sometimes I can’t change pages until I refresh; I suspect the viewer is reloading when UI state changes (e.g., opening the modal/toggling calibration) or an overlay during calibration is stealing clicks so the second point never registers and the viewer stays “frozen.” I’ve stabilized the file URL so it only loads once, guarded the PDF loader, skipped re-rendering the base canvas during calibration, set the overlay to pointer-events: none, and auto-cancel calibration on page change, but I still see the occasional disappear/reload. I’m looking for a robust pattern to keep the base canvas stable while UI state changes, a sanity check that my scale math is right (measure distance in PDF points—1/72″—then compute realFeetPerPoint = realFeet / measuredPdfPoints), and best-practice advice for large sheets (e.g., keep a single raster and use CSS transforms for pan/zoom, re-rasterize only on zoom thresholds, or move to a tiled/DeepZoom-style approach). After I get this solved I also want to use preset scales, like 3/16' = 1' and many others so the user has options to calibrate using two points or select the presets.
