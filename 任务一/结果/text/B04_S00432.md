## 正文
It is common that onClick lambdas (call methods that) perform viewModelScope.launch { ... } . I see a possible race condition here, the viewModelScope may be cancelled before the launched action is complete. Let us consider this scenario when the user chooses one of many options on a separate screen: The user needs to choose an option, goes to the screen with options, taps one option, and after that single tap the application saves the user's choice and navigates back. I see the problem that if navigation happens faster than saving completes, saving will not work (because the whole scope will be cancelled). In theory, this problem may happen even if a separate button is used for navigation, and the user quickly taps two buttons (e.g. with two fingers), or the system is busy and cannot react on the first click before the second click happens. What is the recommended way to handle that? What I currently do probably is an overdesign: I make all ViewModel-s live as long as the Activity lives (in a single-activity app). That is, I actually disable this "view model lifecycle" feature.
