## 正文
I trained a CNN on MNIST for digit recognition that gets ~98% accuracy during local testing (Jupyter/Colab). After deploying it behind a Flask API (React frontend sends canvas-drawn digit images), predictions are frequently wrong — even for digits that look clearly written. I suspect it's a preprocessing mismatch between training and inference, but wanted to confirm the right approach. My training pipeline normalizes images like this: # Training preprocessing image = image.astype('float32') / 255.0 image = image.reshape(1, 28, 28, 1) And my Flask inference endpoint does this with the canvas image sent from the frontend: # Inference preprocessing img = Image.open(io.BytesIO(image_bytes)).convert('L') img = img.resize((28, 28)) img_array = np.array(img) / 255.0 img_array = img_array.reshape(1, 28, 28, 1) Are there common pitfalls when converting a canvas-drawn image (white background, black strokes) to match MNIST's format (black background, white digit)? Also — should resizing use antialiasing/interpolation methods that match how MNIST images were originally downsampled? What's the standard checklist for training/serving preprocessing parity in image classification deployments?
