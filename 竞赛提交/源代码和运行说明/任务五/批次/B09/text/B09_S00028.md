System: Windows 11 Program: Unity 6 Code Editor: Visual Studio Code Disclaimer: English is not my native language, so I am using translation tools. I apologize if the context or phrasing seems strange. I am currently trying to handle the Unity Input System within an ECS (Entity Component System) architecture. I'm struggling to understand why a specific part of my implementation isn't working as expected. I was experimenting with debug code to verify user input reception. Problem: In the process of updating an InputData component within my InputGatheringSystem's OnUpdate method, input reading methods like action.IsPressed() and action.ReadValue() work correctly. However, methods that detect state changes within the frame, specifically action.WasPressedThisFrame(), do not seem to work (they consistently appear to return false, even when the corresponding button is pressed). What I've Tried: I have spent considerable time trying to diagnose this, including asking AI assistants (Gemini, ChatGPT) and performing the following checks: Checked Input Action Asset Settings: Verified the relevant actions (e.g., "Jump", "Attack") are set to Button type. Confirmed no Interactions are added to the bindings. Input System Package settings in Project Settings are default (Update Mode is Process Events In Dynamic Update). Changed System Execution Order: Tried moving the InputGatheringSystem to later update groups (e.g., SimulationSystemGroup, even PresentationSystemGroup) to rule out timing issues related to running too early. (This did not resolve the issue). Verified Not Action-Specific: Confirmed the problem isn't limited to just the "Jump" action. When I changed the code to read the "Attack" action using WasPressedThisFrame, it also failed to detect the press, whereas using IsPressed for "Attack" worked fine. Tried Other Frame-Based Methods: Tested WasReleasedThisFrame and WasPerformedThisFrame. These also failed to return true when expected. Ruled Out Missed Logs: Considered if the Debug.Log for the WasPressedThisFrame check was simply missed because it's only true for one frame. However, careful log checking and searching confirmed no such log was generated, indicating the condition likely never evaluated to true. Current Program Context: My setup follows this basic flow: (Initialization): An InputData component (struct IComponentData) and an identifying tag (PlayerInputSingletonTag) are added to a singleton entity. This is done via an InputSingletonAuthoring MonoBehaviour + Baker attached to a GameObject in a Subscene, which gets baked. (Main Loop Systems): InputGatheringSystem.cs: An ECS SystemBase that runs early (tested in InitializationSystemGroup and SimulationSystemGroup). It uses the C# class generated from my .inputactions asset to poll input states (ReadValue, WasPressedThisFrame, IsPressed) in its OnUpdate method and updates the fields of the singleton InputData component. DebugInputsystem.cs: Another SystemBase designed to run after InputGatheringSystem. It reads the singleton InputData component in its OnUpdate and uses Debug.Log to print the current input values. Suspicions / Questions: Is it possible that WasPressedThisFrame (and related methods like WasPerformedThisFrame, WasReleasedThisFrame) does not function correctly or reliably within the context of an ECS SystemBase OnUpdate method? Is there some known limitation or specific way it needs to be handled in ECS? If my fundamental implementation approach for reading input in ECS is flawed, I would be very grateful for guidance on the correct way to achieve this, specifically for detecting discrete button press events like WasPressedThisFrame.
