# 任务四：机会价值评估与优先级排序

第三届甘肃省大学生数据挖掘挑战赛（本科组）赛题《AI 应用场景的智能挖掘与机会评估系统》。

> **【当前数据口径 · v4】** 输入：任务三的 **55 个主题簇**（`result3.csv`，簇内机会记录为 `Bxx-Sxxxxx` 批号限定，共 1728 条）。
> 输出：`result4.csv`（官方 7 列，**55 行**），按「机会价值分」降序给出优先级。
> 本文件下方如残留“30 簇 / 14 行 / 78.5”等数字，均为历史口径，不得用于当前论文与提交。

## 一、任务目标

对任务三每个主题簇做量化评估：从多源指向度、记录规模及补充维度三维度各打 0~100 分，
加权合成「机会价值分」，排序输出优先级（1 最高）。对应官方列：
`采集批次号, 主题簇编号, 主题簇名称, 功能类别, 所属行业, 机会价值分, 优先级`。

评估对象限定为“公开需求信号上的相对表现”，不是商业价值预测。

## 二、方法

### 1. 三维度评分（实现见 `common/analysis.py: score_clusters`）

| 维度 | 定义 | 归一化（0~100） |
|---|---|---|
| ① 多源指向度 M | 簇内机会记录覆盖的来源网站种类数 | `100 × 来源种类数 / 14`（固定基准），上限 100 |
| ② 记录规模 N | 簇内机会记录条数 | `100 × 条数 / 100`（固定基准），上限 100 |
| ③ 商业信号 Q | `0.7 × 互动热度分 + 0.3 × 需求置信度分` | 见下 |

- 单条互动热度 = 星标数 + 浏览数 + 点赞数 + 评论数 + 收藏数（缺失字段留空，不补零）；
- 簇内**生均**热度经 `log1p` 压缩后除以 `log1p(200000)` 得互动热度分；
- 需求置信度分 = 簇内记录平均机会置信度 × 100（来源：任务二结果）。
- 取生均而非求和，是为了避免“条数多 = 热度高”与规模维度重复计权。

### 2. 权重确定与合成

先验权重 `(0.35, 0.35, 0.30)`；熵权法从 55 簇三维数据算得 `(0.2076, 0.7412, 0.0512)`；
采用 `0.6 × 先验 + 0.4 × 熵权` 并归一化，得 **(0.2930, 0.5065, 0.2005)**。

`机会价值分 = 0.2930 × M + 0.5065 × N + 0.2005 × Q`，保留 1 位小数；同分按记录规模降序。

### 4. 稳健性与指标有效性

`result4_中间指标.json` 内置权重扰动与极端单维检验：偏多源 0.996、偏规模 0.992、偏商业 0.996；
纯规模 0.972（Top5 重合 5/5）、纯多源 0.753（Top5 重合 2/5）。
Spearman 相关（N=55，平均秩）：M–N 0.620、M–Q 0.701、N–Q 0.482、N–总分 0.972、Q–总分 0.632。
结论边界：权重温和扰动下稳健；极端单维（尤其纯多源）不稳健；排序由规模主导，
价值分仅表示需求聚集度与关注度的相对度量。
