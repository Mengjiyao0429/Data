## 正文
I've developed a lookup utility website to take the detailed table reports that the Data Dictionary produces, to parse that output into useable JSON data with PHP, and then to re-display it in a nice tabular form with JS/HTML/CSS. I'm seeking to automate the generation of the detailed table definition files in such a way that it can be scheduled to run with cron, and the resulting definition file(s) can be copied to my website's directory, and be post-processed there into query-friendly data files. But, I'm not finding any CLI commands for the data dictionary. Is there any way to do it outside of the terminal GUI, like this documentation demonstrates? (Edit for clarity) I don't want to programmatically recreate the report from scratch, myself. I want the data dictionary to output the detailed table report cli command, or something similar. Thanks. [update - 4/15/2026] I want to give Tom Bascom full credit, but I want to share a cleansed version of my solution in the hopes that others can learn some tricks for automation. This file can be referenced in crontab. #!/bin/bash progress_mbpro=/usr/128dlc/bin/mbpro projectDir=/a/b/c procFilePath=$projectDir/getDetailedTableReportForDb.p outputLog=$projectDir/stdout.log errorLog=$projectDir/errout.log envPath=/x/y/z databases=( 'db1' 'db2' ... ) for db_name in "${databases[@]}"; do paramFile=$envPath/$db_name.pf dbPath=$envPath/db/$db_name $progress_mbpro $dbPath -pf $paramFile -p $procFilePath -param $db_name >> $outputLog 2>> $errorLog # Wait 10 seconds to alle the output buffers overlapping. sleep 10 done And the getDetailedTableReportForDb.p procedure can contain something like this. def var input-db-name as char. input-db-name = SESSION:PARAMETER. def var v-reportFilePath as char. v-reportFilePath = '/x/y/z/' + input-db-name + '.detailed.all-tables.def'. define new shared stream rpt. find first _Db no-lock. if available _Db then do: output stream rpt to value(v-reportFilePath) page-size 0. // detailed table data report run adecomm/_dtbldat.p( input recid(_Db), input 'ALL', // all tables input 'o' // output report to stream ). output stream rpt close. end. And this is essentially how I generate a series of detailed (ALL) table reports for multiple databases. And writing the PHP code to post-process them is not that complicated since the reports are consistently formatted and labeled, and repeating. Thanks Tom, and others!
