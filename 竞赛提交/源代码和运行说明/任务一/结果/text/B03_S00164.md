# Deploying a RAG agent via Slack: What are the viable approaches?

## 正文
I'm looking for a high-level answer on the pros and cons of different approaches (or being directed towards a clear winner) I'm trying to maximise for speed of deployment, UX, avoiding high api costs, and ease of maintenance. Ideally, a non-technical user should be able to change the source materials easily. I'm not using any sensitive data, so security is not a major concern. Here's an outline of my desired outcome Users message the bot or a channel with their request. In either case, it should be possible for them to ask questions privately. The agent replies, citing source material wherever possible. It should be easy for the user to view the full source material easily (ideally as easy as clicking a hyperlink) A non-technical user should be able to audit usage and view answers, ideally user interface. It should be possible for that user to change the source materials as almost as easily as one could change a Google document. When looking at usage / LLM costs, it should be possible to work out which users/requests are underlying them (e.g., it should be tri to produce a bar chart of cost per user).
