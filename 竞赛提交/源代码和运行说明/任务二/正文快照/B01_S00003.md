# Ask HN: Is anyone running multi/always-on agents that don't cost a fortune?

## 正文
Yesterday a few interesting links appeared on hacker news about always-on [1] and multi-agent setups [2]. Some of those points resonate with what we're experiencing with our current approach of running agents and sub-agents locally. - We are delegating complex and long running tasks to agents more and more. Being able to run those overnight seems like a logical next step in efficiency, because at the moment we are stopping the local agents every evening and restarting them in the morning. - A setup with decentralized multi-agent system with shared context is 5.5x faster than Claude code + native subagents. It takes 29.3 minutes (2% of agent time waiting) versus 162.7 minutes (44% of agent time waiting). [3] This aligns with our feeling that locally running agents are often "doing nothing" while waiting on test results, each other, and so on - The possibility to monitor "input channels" (e.g. chat channels, e-mail inboxes...) and have agents act autonomously on those seems like something that could help us out as well. This all sounds amazing, but we're unsure how others are currently doing this and what those cost. We currently mainly power our needs -based contracts (e.g. claude (code) pro/max, chatgpt plus/pro ...) - Is anyone running such multi-agent or always-on agent systems? - Do you host it yourself, or do you use existings solutions like grok bots or claude remote control sessions or claude routines? - Can you make this work with subscriptions, or do you use API pricing, or even self-hosted LLMs? How do the costs compare with running local agents? - How are the results? Is it an improvement?
