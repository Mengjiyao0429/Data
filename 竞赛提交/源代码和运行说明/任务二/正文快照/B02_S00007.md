# Remove Cloud Image Recognition-specific authentication examples and assumptions

- 来源：GitHub
- 链接：https://github.com/VWS-Python/vws-auth-tools/issues/2010
- 发布时间：2026-10-29

## 正文
PTC has notified customers that Vuforia Engine Cloud Image Recognition retires effective **May 2, 2027**. Existing services remain operational during the notice period; after the end-of-life date, Cloud Image Recognition databases and associated services will no longer be available. Source: the PTC Vuforia Team customer email supplied by the maintainer. Remove support for the retiring cloud image service, including cloud image target management as well as recognition queries. Model Target and VuMark support remain in scope for the project; the email does not announce their retirement. This package contains shared authentication code, so the cloud retirement must not result in deleting the VWS signing scheme wholesale. VuMark generation still uses VWS authentication, while Model Targets use OAuth2/Bearer authentication; see [PTC's authentication guide]( ). Scope: - Replace the README's cloud `GET /targets` example and any cloud-only VWS/Query documentation examples with supported VuMark or Model Target examples. - Remove cloud database/client-access-key and recognition-query-specific claims, configuration, fixtures, or test cases where present. Reframe generic signing tests around VuMark requests where appropriate. - Preserve `authorization_header`, its HMAC signing implementation, and `rfc_1123_date` for VuMark callers. - Preserve `basic_authorization_header` and `bearer_authorization_header` for Model Target OAuth2 token and dataset requests. - Update descriptions/docstrings, documentation, and release notes to describe the remaining supported authentication uses; remove dependencies only if no retained helper requires them. Coordinate with Done when current documentation and tests no longer depend on cloud image recognition, while VuMark VWS signing and Model Target Basic/Bearer helpers remain supported and tested.
