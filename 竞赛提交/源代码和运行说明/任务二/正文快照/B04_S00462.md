# Aks HN: How did you improve the quality of your code base?

## 正文
Our company builds a java openGL CAD/CAM application suite for windows desktops. We have a couple tens of million LOCs, with ~50 projects and 1000s of packages. We grew to ~50 devs. Our teams are distributed worldwide in several locations. After ~10 years of neglection we need a strategy to increase the code quality (lots of dependencies, feature envying inheritance hierarchies, spaghetti code, similar problem are solved in myriad ways, all that jazz). + How do you measure code quality? How do you interpret the metrics? + What are good tools for a windows/java/eclipse dev environment? + How do you act on the metrics and actually improve code quality? + Can you recommend any resources of success stories on how companies managed to increase code quality of a big, tangled system? What we are doing ATM: - code reviews - Jenkins for build + testing (~ 5% code coverage, tests run nightly and take ~1h) - Scrum with 2 week sprints with 30% time allocated for refactor/ writing of tests + 1 week maintenance to work on bugs backlog - small team (2 members) increase GUI tests to automate validation - developing guide lines for reviews and coding
