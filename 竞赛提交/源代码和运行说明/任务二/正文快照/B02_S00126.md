## 正文
I spent the last few years in High-Frequency Trading. In that world, "probabilistic" automation is a non-starter; if an AI hallucinations or clicks the wrong pixel, it's a compliance disaster. Most current AI agents rely on vision (pixels). It’s slow, brittle, and introduces a massive margin of error. I built GodHands to treat desktop apps like structured APIs instead of screenshots. It’s an MCP (Model Context Protocol) server that acts as a deterministic "action layer." The Approach: Object Model > Pixels: Instead of vision, the engine hooks into application object models directly. It maps data structures dynamically so the automation doesn't break when the UI changes. Architect vs. Builder: The LLM acts only as the Architect (intent). A local execution engine acts as the Builder. The AI never "guesses" the math; it triggers verified code primitives. Local-First: All data processing stays on your machine. The LLM handles the reasoning, but the GodHands engine handles the data locally. The Workflow: It bridges siloed apps into a unified protocol—e.g., scraping a Gmail statement, running a cross-sheet reconciliation in Excel, and piping anomalies to Slack or a Calendar invite.
