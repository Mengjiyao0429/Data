## 正文
I am integrating an AI-driven Q&A chat assistant into an existing C# .NET Core 8 CRM application (using PostgreSQL as the primary database). The goal is to allow users to ask natural language questions about CRM data, which the backend will process using the Model Context Protocol (MCP) to fetch data and return an AI-generated response. Proposed Workflow: Frontend (Angular): Sends the user's raw text question to a backend API endpoint ( /api/chat ). Backend API (ASP.NET Core 8): Step A (Intent Classification): Classify the user's request (e.g., Is it a general question, a request to fetch specific CRM data, or an action like creating a lead?). Step B (MCP Tool Execution): Based on the intent, invoke the appropriate MCP server tools to pull data from PostgreSQL or trigger CRM actions. Step C (Response Generation): Take the raw tool/DB response, pass it back to the LLM to format it into a friendly, natural language answer, and return it to the frontend. Where I am Stuck / Confused: Intent Classification Architecture: What is the standard/best practice for implementing the Intent Classifier step in C#? Should this be handled by a lightweight LLM call (using system prompts/Structured Outputs), or is it better to use a dedicated semantic routing library (like Semantic Kernel)? LLM Selection: Which LLM models (e.g., OpenAI, Claude, or open-source models like Llama ) perform best and most reliably for both Intent Classification and MCP tool calling? Flow/State Management: In an ASP.NET Core 8 Web API, what is the cleanest architectural pattern to orchestrate this? Should I look into Agentic frameworks, or build a custom service layer utilizing the official Microsoft.Extensions.AI abstractions? Any Architectural diagrams, or guidance from anyone who has implemented MCP servers with .NET 8 backends would be greatly appreciated!
