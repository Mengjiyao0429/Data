## 正文
I'm experimenting with a documentation architecture aimed at improving how AI coding agents (specifically Cursor agents) understand and navigate a project. The goal is to reduce the amount of code the agent needs to inspect by giving it structured, hierarchical context about the project. Current approach At the top level I maintain an agents.md file that acts as the main reference for the whole project. From there, the documentation branches into smaller .md files distributed throughout the repository, usually one per relevant folder. The idea is a hierarchical documentation structure where: agents.md defines the global rules and conventions. Each lower-level .md acts as an index for the components below it . The structure "capillarizes" down to folder-level documentation. In agents.md I also define how the other .md files should be structured. Structure of each module .md Each documentation file defines two main things: Skill The final product utility of the component. In practice this describes what the component must achieve and what the agent should validate as the definition of done . Spec The current implementation-level behavior: how the component works in code how it interacts with other components what dependencies it has The goal is that the agent can quickly identify which components are relevant without scanning unnecessary parts of the codebase. Update rule Each .md also includes a rule stating that any change to a component must be reflected in both its Skill and Spec sections. Question I'm trying to understand whether this kind of documentation architecture is actually effective for AI-assisted development. Specifically I'm curious about: Is a many-small-md hierarchical structure like this a good approach for AI agents? Or is it generally better to maintain fewer, larger, more centralized documents ? Are people using other patterns that work better with Cursor / AI coding agents? Is this overengineering / unnecessary? I'm especially interested in real-world experience from people working with Cursor or similar AI-assisted workflows. How are you structuring project documentation so that AI agents can navigate large repositories efficiently?
