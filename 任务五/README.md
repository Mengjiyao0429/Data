# 任务五：结果呈现与决策支持

第三届甘肃省大学生数据挖掘挑战赛（本科组）赛题《AI 应用场景的智能挖掘与机会评估系统》。
本文件夹实现赛题任务五的三项要求：**机会选取、决策产出、结果呈现与交互**，并补充系统角色权限、
成本资源与部署运行说明。

## 一、任务目标与实现

| 赛题要求 | 本系统实现 |
|---|---|
| （1）机会选取：以任务四价值分/优先级为主要依据，可选取或推荐高价值主题簇 | 仪表盘按价值分与优先级排序，支持按名称/功能类别/行业/来源覆盖检索筛选，默认推荐 Top1 |
| （2）决策产出：针对选定方向生成立项策划案，导出 Word/Markdown，含目标用户与痛点、核心功能、技术路线、周期、子任务、依据来源、价值评分 | 每个主题簇一键生成立项策划案，可在线预览并下载 Markdown；14 份策划案已预生成在 `示例立项策划案/` |
| （3）结果呈现与交互：仪表盘/可视化图表/交互式查询等形式 | 漏斗图、价值排序条形图、三维度贡献堆叠图、簇×来源热力图、明细表、抽屉式溯源详情 |
| 角色与权限、成本与资源、部署与运行 | 见下文章节，仪表盘内置"系统说明"弹窗 |

## 三、系统功能

1. **总览**：4 个 KPI（5517 条记录、388 条机会、14 个主题簇、最高价值分 99.4）。
2. **图表**：
   - 全流程漏斗（5517 → 388 → 14 → 5）；
   - 主题簇机会价值分与优先级排序；
   - 三维度加权贡献分解（多源 ×0.35 / 规模 ×0.35 / 商业 ×0.30）；
   - 主题簇 × 来源网站热度矩阵。
3. **检索与筛选**：名称/功能类别/行业关键词搜索，行业与功能类别下拉，来源覆盖数量筛选。
4. **溯源详情**：点击任一主题簇，展示三维度得分、来源覆盖明细，以及按热度排序的前 12 条簇内机会记录（可点回原文链接）。
5. **决策产出**：一键生成立项策划案，在线预览，下载 Markdown。

## 四、角色与权限

| 角色 | 操作权限 | 数据可见范围 |
|---|---|---|
| 需求发起者 | 浏览、筛选、检索、查看溯源记录、导出台账/策划案 | 公开渠道采集的记录摘要与原文链接；不含个人信息 |
| 决策者 | 在需求发起者权限之上，对主题簇标记/取消"已立项" | 同上 |

- 立项状态仅保存在本机浏览器（localStorage），不共享、不回传服务端，避免引入账号体系与隐私风险。
- 页面右上角可切换角色，权限差异即时生效（需求发起者不可点击"标记立项"）。

## 五、成本与资源

- **运行成本**：纯静态页面 + 本地数据文件，无服务端、无在线模型调用，完全离线可用。
- **存储**：数据文件约 165 KB，图表库约 1.0 MB，本任务合计约 1.3 MB（含截图）。
- **算力**：采集、判别、聚类、评分均为离线预计算，仪表盘只做读取与渲染，普通笔记本即可运行。
- **可选扩展**：若需多人协作，可将 `dashboard_data.js` 置于内网静态服务器，或接入轻量后端保存立项状态。

## 六、部署与运行

方式一（推荐）：

```bash
cd 仓库根目录
python -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765/任务五/仪表盘/
```

方式二：直接双击 `任务五/仪表盘/index.html`（数据已内嵌为 JS，ECharts 本地化，无需联网）。

重建数据与策划案：

```bash
python 任务五/源码/build_dashboard.py
```

## 七、如何验证

1. 打开仪表盘，KPI 应为 5517 / 388 / 14 / 99.4。
2. 表格 14 行，优先级 1–14，价值分降序，与 `任务四/结果/result4.csv` 一致。
3. 任选一个主题簇，抽屉内的簇内记录编号可在 `任务三/结果/result3.csv` 与 `任务一/结果/result1.csv` 中找到。
4. 点击"生成立项策划案"，第七节"依据来源"列出的记录编号与链接均真实可点。
5. 切换角色为"决策者"，"标记立项"按钮由禁用变为可用；切回"需求发起者"后恢复禁用。

## 八、已知局限

- 主题簇"所属行业"为"其他"时（占比较高），策划案的目标用户与痛点文案使用通用兜底描述；
  这是任务二行业标注口径的直接反映，待任务二行业标注优化后可自动改善。
- 立项状态仅本机保存，不构成真实审批流；如需生产级审批，应接入统一身份与审批系统。
